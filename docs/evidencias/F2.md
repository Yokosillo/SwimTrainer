## 5. Decisiones y ambigüedades

- **`--validar` valida TOML y Markdown** y devuelve 0 solo si ambos están bien. El JSON conserva
  `{ok, errores, avisos}` y añade `markdown`/`toml` con el detalle.
- **Firma pendiente = aviso, no error.** El piloto pide `PA-001`/`PA-002` con `procedencia =
  criterio_firmado` y firma pendiente; F2 no puede inventar la firma. El error es no tener procedencia;
  la firma vacía se avisa y F3-07 la resuelve.
- **Fuentes huérfanas = aviso.** En el piloto solo se citan 4 de las 22 fuentes; las demás quedan
  definidas y sin citar, como pide el plan (aviso, no error).
- **Sincronización en base temporal.** La base real recibe las tablas aditivas al conectar, pero no se
  han volcado filas de conocimiento en `data/entrenador.db`: la sincronización se prueba en
  `:memory:`/`/tmp`. Así no se toca el dato del atleta. `--sincronizar` queda disponible para F3.
- **`calendario.toml`** contiene días de la semana, no fechas ni nombres: es configuración, no un
  identificador personal.
- **El motor sigue en v1.** `conocimiento_toml` no lo importa ningún módulo de decisión; `RG-002` no
  se usa todavía.
