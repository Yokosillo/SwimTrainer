## 2. Contrato

```json
{
  "explicacion": "La prioridad es el ritmo de prueba.",
  "citas": ["AF-002", "FU-002"],
  "cifras": [{"valor": 1700, "unidad": "m", "origen": "recomendacion"}],
  "avisos": [],
  "confianza": "media"
}
```

Validadores:

- JSON objeto y claves obligatorias.
- `citas` solo `AF-*`/`FU-*` presentes en el contexto.
- `cifras[*].valor` presente en el contexto y `origen` en `AF/FU/PA/recomendacion`.
- números de la explicación presentes en el contexto (se ignoran años).
- bloqueo de lenguaje médico y promesas de marca.
- Si falla, `fuente="determinista"` y se guarda `validacion` con el motivo.

## 3. Payload mínimo (sin datos personales)

```json
{

    "revisar_en": "2026-10-27",
    "explicacion_determinista": "Que veo: ...",
    "opcion": {"id": "A", "sesion": "8x100 con 25-30 s", "dia": "jueves", "metros": 1700,
               "ritmo": "1:16", "confianza": 0.7, "riesgo_etiqueta": "medio", "score": 1.5}
  }

```

No se envían FIT, GPX, la base, partes completas, notas personales, nombre/club, credenciales ni
`conocimiento/local`.

## 4. Endpoint y UI

```text
POST /coach
  {"recomendacion": {...}, "pregunta": "..."}
  200 -> {ok, fuente: llm|determinista, explicacion, citas, cifras, avisos, confianza, validacion}
  403 -> capa apagada/sin configurar
  400 -> falta recomendación o cuerpo inválido
```

Con `COACH_ENABLED=0` el endpoint responde 403 y el panel **no** incluye `coach` ni el botón. Con el flag
encendido, la tarjeta F7 pinta “Explicar esta recomendación”; la petición va al servidor local y nunca
lleva la `COACH_API_KEY`.
